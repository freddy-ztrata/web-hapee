Compartir

Durante el último año, la pregunta más repetida de los clientes de Hapee fue la misma: «¿por qué a veces el agente parece menos inteligente cuando le doy mucha información del cliente?». La respuesta técnica era frustrante: los agentes de IA en plataformas tradicionales recortan el contexto antes de mandarlo al modelo, porque cada token cuesta. Resultado: el modelo no ve toda la conversación, no ve el CRM, no ve el historial de compras. Pierde matices.

El Model Context Protocol (MCP), que Anthropic publicó como estándar abierto, resuelve eso. En vez de recibir un prompt fijo, Claude puede pedir contexto adicional en tiempo real a fuentes externas: el CRM, la base de conocimiento, las herramientas. El razonamiento se vuelve de varios pasos de verdad.

Qué cambia, en una línea

Antes: el agente llama una vez al modelo con un prompt fijo. Ahora: el modelo pide los datos que necesita cuando los necesita, razona, pide más y decide. Menos latencia, mejores respuestas.

01Qué es la conexión nativa con Claude

Es la implementación del protocolo de Anthropic dentro de los agentes de Hapee. Cuando un agente está configurado en modo MCP, pone a disposición de Claude estos contextos:

  • CRMContacto, etiquetas, historial, etapa del pipeline y valor estimado.
  • ConversacionesToda la historia del contacto en todos los canales.
  • Base de conocimientoDocumentos, preguntas frecuentes y manuales de tu espacio.
  • CalendariosLa disponibilidad real del equipo, no horarios simulados.
  • Flujos de trabajoPuede disparar automatizaciones desde la conversación.

02Cómo se nota en la práctica

Un ejemplo concreto: una clienta que ya compró tres veces escribe «hola, necesito ayuda con mi pedido». Con un agente clásico, el modelo recibe esa frase y un prompt de sistema fijo. Con MCP, Claude pregunta primero al CRM si esta persona tiene pedidos abiertos: ve uno «en tránsito», la fecha estimada de entrega y un ticket que abrió ayer. Solo entonces responde:

«¡Hola, Camila! Veo que tu pedido #4892 sale hoy de bodega y debería llegarte mañana entre 10:00 y 14:00. ¿Escribes por eso o pasó algo más con el ticket que abriste ayer sobre la talla?»Respuesta generada con la conexión nativa con Claude

La diferencia es que suena humano, porque tiene todo el contexto y no un prompt recortado. Así se ve la secuencia por dentro:

Traza del agente (simplificada)
# mensaje entrante · WhatsApp
cliente: "hola, necesito ayuda con mi pedido"

→ crm.buscar_contacto(telefono="+56 9 •••• 4821")
← { nombre: "Camila", compras: 3, pedidos_abiertos: [4892] }
→ pedidos.obtener(id=4892)
← { estado: "en tránsito", entrega: "mañana 10:00–14:00" }
→ tickets.recientes(contacto="Camila")
← [{ asunto: "cambio de talla", abierto: "ayer" }]

04Cómo lo activo

Disponible para todos los clientes de Hapee. Son cuatro pasos:

  1. Elige el modelo del agente

    En la configuración de modelos de IA de tu agente, elige Claude (conexión nativa vía MCP) en vez de las opciones de API tradicionales.

  2. Conecta los contextos

    Por defecto, Hapee expone el CRM, las conversaciones, la base de conocimiento y el calendario. Puedes desactivar cada uno si no quieres que el modelo acceda a algo.

  3. Prueba en el entorno de pruebas

    Haz una conversación de prueba con tu propio número. Vas a notar la menor latencia de inmediato.

  4. Pasa a producción

    Activas MCP para todos los agentes de un espacio de trabajo con un interruptor.
