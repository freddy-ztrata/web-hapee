O Fable Mythos chega ao Hapee: mais poder para a conexão MCP

A Anthropic acaba de apresentar o Fable Mythos, uma nova incorporação à família de modelos Fable do Claude. No Hapee já estamos preparando sua integração para somá-lo à conexão nativa que temos com o Claude via Model Context Protocol — a mesma stack com a qual hoje nossos agentes raciocinam, recuperam contexto e resolvem conversas em produção.

10 jun 2026 Produto · Tech 3 min de leitura Por Equipe Hapee

Há um mês lançamos a conexão nativa com o Claude via MCP: os agentes do Hapee deixaram de chamar o Claude por API e passaram a invocá-lo como contexto direto. Menor latência, raciocínio multi-passo de verdade, melhor uso do contexto do cliente. Essa base é a que hoje nos permite seguir somando capacidades sem reescrever nada.

Esta semana a Anthropic apresentou o Fable Mythos, uma nova variante da sua família Fable. É muito recente — está disponível há poucos dias — e ainda estamos testando a fundo. Mas a direção é clara: ele vai se somar à stack de modelos Fable que já usamos no Hapee para potencializar o raciocínio dos agentes.

O que é a família Fable e como a usamos

O Hapee já integra vários modelos Fable como parte da sua camada de raciocínio. Cada cliente pode escolher o que melhor se adapta ao seu caso de uso, e os agentes podem alternar entre eles conforme a tarefa: classificação rápida, conversa longa, raciocínio estruturado, recuperação de contexto a partir do CRM, leitura da base de conhecimento, etc.

A vantagem de tê-los todos atrás do mesmo servidor MCP do Hapee é que a troca entre modelos é invisível para o cliente final e, para a equipe que opera o agente, é um toggle na configuração. Não é preciso reescrever prompts nem mover dados.

O que o Mythos soma à stack

O Mythos está se desenhando como uma variante orientada a continuidade e raciocínio prolongado em conversas longas. Na prática, isso significa agentes que mantêm melhor o fio quando o cliente muda de assunto, volta a uma conversa anterior ou entra em um funil de vários turnos.

Não prometemos benchmarks específicos: o modelo é muito novo. O que podemos dizer é que a arquitetura MCP do Hapee foi desenhada para que, assim que o Mythos estiver pronto para produção, os agentes existentes possam adotá-lo sem migrações complexas. É a mesma conexão, com mais um modelo.

O que importa

O Hapee não depende de um único modelo. A conexão nativa via MCP nos permite incorporar cada nova variante do Claude — incluindo o Fable Mythos — assim que a Anthropic a libera, sem mexer na lógica dos agentes que já operam em produção.

O papel do Claude Code no caminho

Internamente, a equipe do Hapee usa o Claude Code para iterar no servidor MCP, manter integrações, escrever documentação e testar novas variantes assim que saem. É parte do que nos permite estar prontos para incorporar modelos novos em questão de dias, não semanas.

Isso não é teoria: é o padrão com que construímos a conexão MCP original, o que estamos usando agora com o Mythos e o que vamos continuar usando com cada variante que vier.

O que muda para os clientes do Hapee hoje

No curto prazo: nada que você precise fazer. Se você já opera seu agente do Hapee com a conexão MCP nativa, está na mesma infraestrutura que receberá o Mythos quando estiver pronto para uso geral. Vamos comunicar neste mesmo blog e na mudança de versão do produto.

Para os clientes que ainda não migraram para a conexão MCP, o caminho continua o mesmo: ativar o MCP no seu workspace, conectar contexto (CRM, conversas, base de conhecimento, calendário) e deixar os agentes raciocinarem com a informação completa. Cada modelo Fable que somamos à stack opera sobre essa mesma base.
